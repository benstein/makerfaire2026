
🚨 MASTER PROMPT FOR CLAUDE CODE

You are building a browser-based, real-time evolving game designed for a live maker faire exhibit with children.

This is not just a game. It is a continuously evolving artifact that changes throughout the day based on user requests.

Your goals:
	•	Be fast, robust, and visually satisfying
	•	Support frequent live edits
	•	Never break the core loop
	•	Optimize for 1-minute play sessions
	•	Make changes modular and safe

⸻

🎮 CORE GAME SPEC

Game Concept

A top-down arena survival game.
	•	Player controls a character in a fixed-size arena (no scrolling by default)
	•	Enemies spawn continuously
	•	Objective: survive and defeat enemies for 60 seconds
	•	If player dies → immediate game over
	•	If timer completes → victory

Constraints (DO NOT BREAK THESE)

These are sacred systems:
	•	Player movement must always work
	•	Game must always start, run, and end cleanly
	•	Collision detection must function
	•	Timer must exist and complete (~60 seconds)
	•	Game must remain playable with Xbox controller

If a requested change conflicts with these, adapt the idea instead of breaking the system

⸻

🕹 CONTROLS (FIXED)

Use Gamepad API (Xbox controller):
	•	Left stick → movement
	•	A button → primary action (attack/shoot)
	•	Start → restart game

⚠️ NEVER change controls unless explicitly told:

“modify controls”

⸻

🧱 INITIAL BASELINE (START SIMPLE)

Start with:
	•	Player = white square
	•	Enemies = red squares
	•	Projectiles = small white dots
	•	Background = dark gray
	•	Arena = fixed rectangular bounds

Minimal but clean.

⸻

🔁 GAME LOOP
	•	Spawn enemies at edges
	•	Enemies move toward player
	•	Player can attack
	•	Collisions reduce health or destroy entities
	•	Game ends on:
	•	Player death
	•	Timer completion

Keep loop tight and responsive.

⸻

🎨 RENDERING

Use:

	•	Must run smoothly in Chrome on Mac

Design goals:
	•	Clean
	•	Responsive
	•	No heavy dependencies
